שיעור אחת נקודה שש — חיבור WhatsApp Business API למערכות: Make ו-n8n, תמחור ודגשים ישראליים.

שלום וברוכים הבאים. בשיעורים הקודמים בנינו אוטומציות עם Make ועם n8n — Scenarios, Routers, Error Handling, Agent-to-Agent. כל האוטומציות האלה מתרחשות מאחורי הקלעים.

היום נגיע ללקוח. ישירות לטלפון שלו.

WhatsApp הוא הצינור שבו רוב הלקוחות בישראל רוצים לתקשר עם עסקים. לא מייל, לא טפסים באתר — וואטסאפ. ולדעת איך לחבר אותו לאוטומציות שלכם — זה אחד הדברים הכי שווים שתלמדו בקורס הזה מבחינה עסקית.

[מעבר שקף]

בואו נבין למה זה כל כך חשוב בישראל ספציפית.

ישראל היא אחת המדינות עם שיעורי חדירת WhatsApp הגבוהים ביותר בעולם — תשעים ותשעה אחוז מהאוכלוסייה משתמשים ב-WhatsApp. זה לא סתם אפליקציה — זה הערוץ הראשי לתקשורת יומיומית. WhatsApp הוא הפלטפורמה הדיגיטלית מספר אחת בישראל, לפני YouTube ולפני Facebook.

מה זה אומר לעסקים? שלקוחות מצפים לקבל הודעות, אישורים, עדכונים, ותמיכה דרך WhatsApp. חברות שמספקות את זה מקבלות שיעורי פתיחה של שמונים עד תשעים אחוז. לעומת מיילים שמגיעים לעשרים אחוז פתיחה בממוצע.

ישראל הפכה את WhatsApp לשכבת התקשורת העסקית שלה. רופאים, עורכי דין, חשמלאים, מסעדות — כולם מנהלים עסקים דרך וואטסאפ. לקוחות שמתקשרים מקבלים תא קולי, אבל WhatsApp מקבל מענה מידי. זהו השוק שבו אנחנו עובדים.

[מעבר שקף]

לפני שנצלול לטכנולוגיה, חשוב להבין שיש שלוש דרכים שונות לשלוח הודעות WhatsApp מאוטומציה.

הדרך הראשונה — WhatsApp אישי. יש כלים שמפעילים WhatsApp אישי דרך חיבור לדפדפן. זה עובד, אבל Meta אוסרת על זה בתנאי השימוש. מספרים נחסמים. לא נדבר על זה.

הדרך השנייה — WhatsApp Business App. האפליקציה לעסקים קטנים. מגבלה של מאתיים וחמישים ושישה אנשי קשר לשידור, לא ניתנת לאוטומציה אמיתית, לא מאפשרת API. מתאים לעסק עם פחות מחמישים שיחות ביום.

הדרך השלישית — WhatsApp Business API. זה מה שנלמד היום. פלטפורמה רשמית שמטא פתחה לעסקים. מאפשרת שליחת מיליוני הודעות, חיבור לכל מערכת דרך Webhook, שידורים לרשימות ללא הגבלה, ובוטים אוטומטיים. זה הכלי המקצועי.

[מעבר שקף]

WhatsApp Business API בנוי משלוש שכבות.

השכבה הראשונה — Meta, שהם WhatsApp. הם מחזיקים את התשתית. כל הודעה עוברת דרך השרתים שלהם. הם גובים את התשלום ומנהלים את הפוליסה.

השכבה השנייה — BSP, שנקרא Business Solution Provider. אלו חברות שמטא הסמיכה לתפעל את ה-API עבור עסקים. דוגמאות: 360dialog, Twilio, MessageBird, Infobip. בישראל יש גם Vibrate ו-Lynxbe עם ממשק בעברית ותמיכה מקומית.

השכבה השלישית — אתם. מחברים את ה-API ל-Webhook שלכם ב-Make או ב-n8n.

מטא גם פתחה אפשרות ישירה דרך Meta Business Manager בלי BSP — נקרא Cloud API. זה הכי פשוט, ללא עלות נוספת מעבר לשימוש, ועל זה נתמקד היום.

[מעבר שקף]

כדי להשתמש ב-API צריך שני דברים.

ראשון — WABA, WhatsApp Business Account. זה החשבון הרשמי שלכם אצל מטא. נוצר דרך Meta Business Manager. לכל WABA אפשר לחבר מספר מספרי טלפון.

שני — מספר טלפון ייעודי. חובה מספר חדש שלא שימש בעבר ב-WhatsApp שום מכשיר. בישראל — מספר 05X שמעולם לא רשם חשבון וואטסאפ.

תהליך הרישום: שלב ראשון — Meta Business Manager, business.facebook.com, אמתו את העסק. שלב שני — WhatsApp, תחת Business Settings, לחצו Add WhatsApp Account. שלב שלישי — הכניסו מספר טלפון. מטא שולחת SMS עם קוד אימות. שלב רביעי — צרו Meta App ב-developers.facebook.com, הפעילו WhatsApp Product, וקבלו Access Token קבוע. שלב חמישי — הגדירו Webhook URL — ה-URL של Make או n8n שלכם.

[מעבר שקף]

ב-WhatsApp Business API יש שני סוגי הודעות שחשוב להבין.

Template Messages — הודעות שנשלחות ביוזמת העסק, גם כשלא הייתה הודעה מהלקוח ב-24 שעות האחרונות. כל Template חייב לעבור אישור מטא לפני שאפשר להשתמש בו. כיום זה לוקח שעות עד יום. מכילות פרמטרים שאפשר למלא, כמו שם הלקוח ותאריך הפגישה.

Session Messages — הודעות שנשלחות בתוך חלון של עשרים וארבע שעות מאז ההודעה האחרונה של הלקוח. כאן אין צורך ב-Template — אפשר לשלוח כל תוכן חופשי. גם תמונות, מסמכים, ואינטראקציות עם כפתורים.

[מעבר שקף]

תמחור WhatsApp API עבר שינוי מהותי ביולי שתיים אלפים ועשרים וחמש. לפני כן חייבו לפי שיחה — חלון של עשרים וארבע שעות. מיולי 2025 — חיוב לפי הודעה. חשוב להבין את המודל הנוכחי כדי לתמחר לקוחות נכון.

ארבע קטגוריות עם מחירים שונים בישראל:

Marketing — הודעות שיווקיות, מבצעים, קמפיינים. בישראל: כשלושה סנט וחצי לכל הודעה. כן, פחות ממה שאולי חשבתם.

Utility — עדכונים תפעוליים שהלקוח ביקש: אישור הזמנה, עדכון משלוח, קוד OTP. בישראל: כחצי סנט להודעה.

Authentication — קודי אימות חד פעמיים. בישראל: כחצי סנט להודעה.

Service — הודעה שנשלחת בתגובה לפנייה של הלקוח — הלקוח כתב ראשון. חינם לגמרי! שיחות Service אינן עולות כלום.

בנוסף — אם לקוח לחץ על פרסומת בפייסבוק או אינסטגרם ופתח שיחת WhatsApp, כל ההודעות הראשונות בשבעים ושתיים שעות — חינם לגמרי, כולל Marketing.

[מעבר שקף]

בואו נחשב דוגמה אמיתית. רשת של עשרה סלוני יופי. כל חודש: שלש מאות תזכורות פגישה — Utility — כ-עשרה שקל. אלף הודעות שיווקיות — Marketing — כ-ארבעים וחמישה שקל. שלש מאות שיחות תמיכה — Service — חינם. סה"כ: כחמישים וחמישה שקל לחודש בלבד על הודעות.

בנוסף עלות Make או n8n. את המערכת תגבו בחמש מאות עד שמונה מאות שקל בחודש ללקוח — זה מוצר שמוכר בקלות כי הלקוח מרגיש ערך ברור.

[מעבר שקף]

עכשיו בונים. נתחיל עם Make.com.

השלב הראשון — הגדרת Webhook ב-Meta Business Manager. ב-Make: צרו Scenario חדש. הוסיפו Trigger — WhatsApp Business Cloud ואחר כך Watch Events. Make מייצרת Webhook URL אוטומטית.

ב-Meta Developer Console: תחת WhatsApp ואחר כך Configuration, הכניסו את ה-URL של Make כ-Webhook URL. מטא שולחת GET request לאימות — Make מאשרת אוטומטית. Subscribe לאירוע messages.

מעכשיו — כל הודעה שלקוח שולח למספר שלנו תגיע ל-Make כ-JSON.

ה-JSON שמגיע מ-WhatsApp הוא מבנה מקונן. הנתיב לתוכן ההודעה: entry.changes.value.messages.text.body. הנתיב למספר השולח: entry.changes.value.messages.from. ב-Make תשתמשו ב-Data Mapping לחילוץ הערכים.

[מעבר שקף]

טיפ קריטי שכולם שוכחים: WhatsApp שולחת גם Status Updates — אישורי קריאה, אישורי שליחה. אלה לא הודעות אמיתיות. בלי סינון, ה-Scenario שלכם יירוץ על כל אישור קריאה ויבזבז Credits.

הפתרון: Filter מיד אחרי ה-Webhook. תנאי: type = text. רק הודעות מסוג טקסט ממשיכות.

שליחת תגובה: הוסיפו Module של HTTP Request. Method POST. URL: graph.facebook.com עם מספר גרסה ו-PHONE_NUMBER_ID ואחר כך messages. Headers: Authorization עם Bearer ו-ACCESS_TOKEN. Body: JSON עם messaging_product whatsapp, to שהוא מספר השולח, type text, ו-text.body שהוא התגובה.

[מעבר שקף]

אותו דבר ב-n8n — עם הבדל אחד חשוב שצריך לדעת.

ב-n8n יוצרים Webhook Trigger רגיל. אבל כשמגדירים את ה-Webhook ב-Meta, מטא שולחת GET request לאימות לפני שמתחילה לשלוח POST. ב-n8n צריך לטפל בזה ידנית.

הפתרון: Switch Node ראשון. אם Method = GET — מחזירים את ה-hub.challenge שמטא שלחה כפרמטר. אם Method = POST — ממשיכים לעיבוד. בלי הטיפול בה-GET, מטא לא תאשר את ה-Webhook.

ב-n8n יש גם Node ייעודי לוואטסאפ — WhatsApp Business Cloud. הוא נוח במיוחד לשליחת Templates, כי יש שם ממשק ויזואלי לבחירת Template ומילוי פרמטרים. לשליחת הודעות חופשיות — HTTP Request עדיין הכי גמיש.

[מעבר שקף]

חמישה Use Cases שמוכרים בישראל.

הראשון — תזכורות פגישות. קליניקות, קוסמטיקאיות, מאמני כושר. הלקוח קובע פגישה. אוטומציה שולחת תזכורת WhatsApp יום לפני ושעתיים לפני, עם אפשרות לאישור וביטול בלחיצה. שיעור ביטול יורד עד ארבעים אחוז.

השני — Follow-up לידים. ליד ממלא טופס. מקבל WhatsApp מיידי. אחרי עשרים וארבע שעות — תזכורת אוטומטית אם לא טופל. שיעורי המרה עולים בשלושים עד ארבעים אחוז.

השלישי — עדכוני הזמנות. אישור הזמנה, עדכון שיצא למשלוח, הודעה שהגיע. לקוחות שמחים יותר, פחות שיחות לשירות לקוחות.

הרביעי — בוט שאלות נפוצות. בוט עם AI עונה אוטומטית לשאלות חוזרות. נציגים מתפנים לשאלות מורכבות.

החמישי — גביית חובות. תזכורת תשלום מנומסת. קישור לתשלום. תזכורת שנייה ושלישית. שיעורי גבייה עולים.

[מעבר שקף]

כמה נקודות ספציפיות לשוק הישראלי שאסור לשכוח.

מספר ישראלי. לקוחות ישראלים מגיבים הרבה יותר למספר ישראלי שמוכר. מספר בינלאומי נראה חשוד.

תזמון. אל תשלחו WhatsApp עסקי אחרי תשע בלילה ולפני שמונה בבוקר. הוסיפו לוגיקה של שעות פעילות לכל Scenario.

שבת ויום טוב. הוסיפו לוגיקה שלא שולחת בשבת. לא בגלל חוק — בגלל שלקוחות יקבלו WhatsApp בשבת ויתרגזו.

שפה. ישראלים אוהבים עברית. גם אם האנגלית בסדר, WhatsApp בעברית מרגיש יותר אישי ואמין. כתבו Templates בעברית.

[מעבר שקף]

Templates הם הלב של WhatsApp עסקי. בלי Templates — אפשר לשלוח רק בתגובה. עם Templates — אפשר לפתוח שיחה יזומה.

יוצרים Template ב-Meta Business Manager. עוברים ל-WhatsApp Manager ואחר כך Message Templates. בוחרים Category: Marketing, Utility, או Authentication. שם: snake_case כמו appointment_reminder. Language: Hebrew, he. Content עם פרמטרים: הפרמטר הראשון, הפרמטר השני.

לדוגמה: "שלום [שם לקוח], תזכורת לפגישתך ב-[תאריך] בשעה [שעה]. לאישור השב 'כן', לביטול השב 'לא'." מאז אפריל שתיים אלפים ועשרים וחמש — אם שלחתם Template כ-Utility אבל מטא מסווגת אותו כ-Marketing, הוא פשוט מאושר כ-Marketing, לא נדחה. הרבה יותר קל לעבוד.

[מעבר שקף]

Interactive Messages — כפתורים ורשימות — זמינים רק בתוך חלון ה-24 שעות מאז הודעת הלקוח.

שני סוגים עיקריים: Reply Buttons — עד שלושה כפתורים מוגדרים מראש. לקוח לוחץ — מגיע לכם button_reply עם ה-ID שהגדרתם. ו-List Message — תפריט עם עד עשרה אפשרויות. לקוח בוחר — מגיע list_reply.

ב-Scenario שלכם — הוסיפו Switch Node שמסתעף לפי type של הודעה: text לעיבוד רגיל, button_reply לטיפול בלחיצת כפתור, list_reply לבחירה מרשימה. כל אחד מקבל טיפול שונה.

[מעבר שקף]

בואו נבנה ביחד מערכת שלמה — בוט שירות לקוחות עם זיכרון.

התרחיש: לקוח שולח הודעה. הבוט בודק ב-Google Sheets אם הלקוח קיים לפי מספר טלפון. אם כן — מוסיף את ההיסטוריה ל-Context. עונה עם AI מותאם אישית.

ב-Make: Webhook, Filter לסוג text, Google Sheets Search Row לפי מספר טלפון, Set Variable עם שם והיסטוריה, Claude או ChatGPT עם System Prompt שכולל את הפרטים, HTTP שולח תגובה, Google Sheets Update Row לשמירת ההיחלפות.

System Prompt: "אתה עוזר לקוחות. הלקוח הנוכחי הוא [שם]. היסטוריית השיחה האחרונה שלו: [היסטוריה]. ענה בידידותיות ובעברית. אל תחרוג מהנושא."

Google Sheets משמש כ-Memory בסיסי. לפרויקטים גדולים יותר — שדרגו ל-Supabase. אבל לרוב הלקוחות הקטנים Sheets מספיק מצוין.

[מעבר שקף]

לסיכום שיעור אחת נקודה שש:

WhatsApp Business API — ארכיטקטורה ורישום. Meta Cloud API ישירות — ללא BSP, ללא עלות נוספת. WABA, מספר ישראלי, Access Token קבוע.

תמחור — Marketing כשלושה סנט וחצי להודעה בישראל. Utility כחצי סנט. Service חינם לגמרי. שיחה מ-Meta Ads — 72 שעות חינם.

חיבור ל-Make — WhatsApp Watch Events Trigger, Filter type=text, HTTP Request לשליחה. ל-n8n — Switch Node לאימות GET, ואז עיבוד POST, WA Node לשליחת Templates.

Templates — אישור מטא, פרמטרים, שעות ממאפריל 2025 — מסווג אוטומטית ולא נדחה.

דגשים ישראליים — מספר ישראלי, שעות פעילות, שבת, עברית, חמישה use cases עם תמחור מוכן.

בשיעור הבא — שיעור אחת נקודה תשע — נלמד Google Sheets ו-Airtable כבסיס נתונים לאוטומציות. נראה איך ה-Spreadsheet הפשוט הופך לכלי עוצמתי שמחבר בין כל האוטומציות שבנינו.

תודה על תשומת הלב. נתראה בשיעור הבא.
